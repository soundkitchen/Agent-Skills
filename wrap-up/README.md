# wrap-up

セッション(スレッド)を閉じる前の片付けをする skill。やり残し(未コミット・未 push の変更、古くなったドキュメント、起動したままのサーバー、マージ済みのブランチや worktree)を洗い出す。機械的なものはその場で片付け、残りの作業は Issue・PR のコメント・docs など、ふさわしい場所に引き継ぐ。

## 前提

- git リポジトリで使うことを想定している(git でなければ、git まわりの確認は飛ばす)
- Issue・PR まわりを扱うには、[GitHub CLI](https://cli.github.com/)(`gh`)がインストール・認証済みであること(なければ、その確認は飛ばす)

## 使い方

```
/wrap-up
/wrap-up dev サーバーは残して
```

「ここで区切りましょう」「ここで終わります」「今日はここまでにしましょう」「閉じる前にやっておくべきことはありますか?」のような依頼でも起動する。ただし、起動するかどうかは Claude が依頼の意図から判断するので、確実に動かしたいときは `/wrap-up` で呼ぶ。引数やメッセージで「〜は残して」「docs は見なくていい」などと伝えると、既定の動きより優先される。

## 主な挙動

1. **やり残しを洗い出す。** リポジトリの状態と、このセッションの会話の両方を見る。会話からは、終わっていない作業、「あとで」「別 Issue に」と先送りしたもの、会話の中にしかない決定事項などを拾う
2. **機械的なものは、確認なしで片付ける**
   - このセッションで起動したサーバーなどのプロセスを止める
   - 今のブランチがマージ済みなら、main に切り替えて最新にする
   - マージ済みで変更の残っていない worktree を消す(メインの worktree と、このセッションが作業している worktree は消さない)
   - マージ済みのローカルブランチを消す(`git branch -d`。リモートのブランチは消さない)
   - 「マージ済み」とみなすのは、PR がマージされたものか、upstream が消えたものだけ。main から切ったばかりでコミットのないブランチは、ほかのセッションが作業を始めたところかもしれないので消さない
3. **判断が要るものは、一覧にして確認する。** コミット・push・docs の更新・一時ファイルの削除と、残りの作業の引き継ぎ先を提案し、どれを行うか聞く
4. **認められたものだけを行う**
5. **報告する。** 何を片付けたか、どこに引き継いだか(リンク付き)、次のセッションはどこから始めればよいかを伝える

ユーザーが作ったものや、ほかのセッションのものには手を出さない。判断がつかないものは報告にとどめる。セッションは終了しない(閉じるのはユーザー)。

## 引き継ぎ先

専用の引き継ぎファイルは作らず、内容ごとに、人がふだん見る場所に残す。

| 内容 | 引き継ぎ先 |
|---|---|
| 残った作業・先送りしたもの・見つけたバグ | 新しい Issue、または関係する Issue へのコメント |
| 開いている PR の状況(済んだこと・残り・次の一手) | その PR へのコメント |
| 仕様・設計上の決定・手順 | `docs/` の該当ファイル(エージェント向けのルールなら CLAUDE.md) |
| プロジェクトが TODO.md などで管理しているタスク | そのファイル |

挙動の詳細は [SKILL.md](SKILL.md) を参照。
